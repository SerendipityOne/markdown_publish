    基于 URDF 复刻 Burger 仿真、SLAM 与 Nav2

    目标环境：Ubuntu 24.04 + ROS 2 Jazzy + Gazebo Harmonic。

    本文不修改 TurtleBot3 Burger 的尺寸、质量、轮距或雷达参数，而是在自己的 ROS 2 包中复刻其模型、仿真、建图和导航链路。完成后，不再通过 turtlebot3_gazebo 的 launch 启动仿真。

    1. 最终目标

    新建一个独立包 my_tb3_slam_nav2，其职责如下：

    flowchart LR
    U["URDF\n机器人结构与 TF"] --> R[robot_state_publisher]
    S["SDF\n物理、差速驱动、雷达"] --> G[Gazebo Harmonic]
    G --> B[ros_gz_bridge]
    B --> T["/clock /scan /odom /tf"]
    T --> SLAM[slam_toolbox]
    SLAM --> M["地图 YAML + PGM"]
    M --> N["AMCL + Nav2"]
    N --> C["/cmd_vel"]
    C --> B

    最终应满足：

    1. ros2 launch my_tb3_slam_nav2 sim.launch.py 可启动自己的 Burger 仿真。
    2. /clock、/scan、/odom、/tf、/cmd_vel 接口完整。
    3. 可用 slam_toolbox 建图并保存地图。
    4. 可加载地图，手动初始化 AMCL 位姿后用 Nav2 导航。

    !!! warning "URDF 不等于 Gazebo 模型"

    URDF 负责机器人 link、joint、碰撞体和 `robot_state_publisher` 的 TF。Gazebo Harmonic 中的差速驱动、里程计、雷达传感器与噪声由 SDF 中的 Gazebo System 插件定义。只复制 URDF 会得到可显示的模型，但不会得到 `/scan`、`/odom` 或可运动的小车。

    2. 先理解上游文件的职责

    本工作空间已经包含两个上游仓库：

    文件或目录 用途 本项目如何使用
    turtlebot3_description/urdf/turtlebot3_burger.urdf Burger 的原始结构参考 对照 link、joint、惯量和尺寸
    turtlebot3_gazebo/urdf/turtlebot3_burger.urdf 已展开、可直接交给 robot_state_publisher 的 URDF 复制为本项目的 URDF 输入
    turtlebot3_gazebo/models/turtlebot3_burger/model.sdf Gazebo 物理、传感器、差速驱动 复制为本项目的仿真模型
    turtlebot3_gazebo/models/turtlebot3_common SDF 使用的网格模型 原样复制，供 model:// 查找
    turtlebot3_gazebo/worlds/turtlebot3_world.world 仿真场景 原样复制
    turtlebot3_gazebo/params/turtlebot3_burger_bridge.yaml Gazebo 与 ROS 2 的话题桥接 原样复制
    turtlebot3_navigation2/param/burger.yaml Burger 的 Nav2 参数基线 复制后作为本项目导航参数

    turtlebot3_description 中的 URDF 含 xacro 变量；本项目直接使用 turtlebot3_gazebo/urdf/turtlebot3_burger.urdf，因为它已经把 frame 名称展开为普通字符串，适合直接传给 robot_state_publisher。

    3. 创建独立包与复制资产

    以下命令默认工作空间为 ~/tb3_jazzy_ws。先加载 ROS 环境：

    cd ~/tb3_jazzy_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash

    创建包和目录：

    cd ~/tb3_jazzy_ws/src
ros2 pkg create my_tb3_slam_nav2 \
  --build-type ament_cmake \
  --dependencies ros_gz_bridge ros_gz_sim robot_state_publisher

cd my_tb3_slam_nav2
mkdir -p launch models params rviz urdf worlds map

    复制 Burger 的必需资产。这里复制的是源码中的文件，因此后续只改自己的包，不改上游包：

    cd ~/tb3_jazzy_ws

cp src/turtlebot3_simulations/turtlebot3_gazebo/urdf/turtlebot3_burger.urdf \
  src/my_tb3_slam_nav2/urdf/
cp -a src/turtlebot3_simulations/turtlebot3_gazebo/models/turtlebot3_burger \
  src/my_tb3_slam_nav2/models/
cp -a src/turtlebot3_simulations/turtlebot3_gazebo/models/turtlebot3_common \
  src/my_tb3_slam_nav2/models/
cp -a src/turtlebot3_simulations/turtlebot3_gazebo/models/turtlebot3_world \
  src/my_tb3_slam_nav2/models/
cp src/turtlebot3_simulations/turtlebot3_gazebo/worlds/turtlebot3_world.world \
  src/my_tb3_slam_nav2/worlds/
cp src/turtlebot3_simulations/turtlebot3_gazebo/params/turtlebot3_burger_bridge.yaml \
  src/my_tb3_slam_nav2/params/bridge.yaml
cp src/turtlebot3/turtlebot3_navigation2/param/burger.yaml \
  src/my_tb3_slam_nav2/params/nav2.yaml
cp src/turtlebot3/turtlebot3_navigation2/rviz/tb3_navigation2.rviz \
  src/my_tb3_slam_nav2/rviz/tb3_navigation2.rviz

    将 URDF 的网格 URI 从上游包改到自己的包：

    sed -i 's#package://turtlebot3_gazebo/#package://my_tb3_slam_nav2/#g' \
  ~/tb3_jazzy_ws/src/my_tb3_slam_nav2/urdf/turtlebot3_burger.urdf

    此时目录应为：

    my_tb3_slam_nav2/
├── CMakeLists.txt
├── package.xml
├── launch/
│   ├── sim.launch.py
│   ├── slam.launch.py
│   └── nav.launch.py
├── map/
├── models/
│   ├── turtlebot3_burger/
│   ├── turtlebot3_common/
│   └── turtlebot3_world/
├── params/
│   ├── bridge.yaml
│   └── nav2.yaml
├── rviz/tb3_navigation2.rviz
├── urdf/turtlebot3_burger.urdf
└── worlds/turtlebot3_world.world

    4. 关键模型契约

    复刻阶段不要随意改下表内容。它们必须在 URDF、SDF、桥接配置和 Nav2 参数中保持一致。

    约束 当前值 原因
    机器人根 frame base_footprint Gazebo 差速驱动的 odom 子 frame，也是 AMCL 基座 frame
    车体 frame base_link Nav2 costmap 和 BT Navigator 使用的机器人主体 frame
    雷达 frame base_scan /scan.header.frame_id，必须可由 TF 查询
    里程计 frame odom SDF DiffDrive 插件发布
    地图 frame map slam_toolbox 或 AMCL 发布 map -> odom
    速度话题 /cmd_vel，TwistStamped SDF DiffDrive 插件接收，桥接文件已声明此类型
    雷达话题 /scan，LaserScan SLAM、AMCL、全局/局部 costmap 的共同输入

    TF 树应始终连通：

    map -> odom -> base_footprint -> base_link -> base_scan
    • base_footprint -> base_link -> base_scan：由本包 URDF 和 /joint_states 经 robot_state_publisher 发布。
    • odom -> base_footprint：由 SDF 中 gz::sim::systems::DiffDrive 发布，再由桥接转入 ROS 2。
    • map -> odom：建图时由 slam_toolbox 发布；定位导航时由 AMCL 发布。二者不能同时运行。

    !!! warning "SDF 与 URDF 的重复不是错误"

    SDF 的 `wheel_left_joint`、`wheel_right_joint`、`base_scan` 及其相对位姿必须与 URDF 对应项一致。前者服务 Gazebo 物理，后者服务 ROS TF；两份模型不一致会表现为激光在 RViz 中偏移、里程计与模型不同步或 Nav2 碰撞体积异常。

    5. 使包可被安装

    将 CMakeLists.txt 简化为只安装资产和 launch 文件。本项目没有自定义 ROS 节点，不需要写 C++ 或 Python 节点：

    cmake_minimum_required(VERSION 3.8)
project(my_tb3_slam_nav2)

find_package(ament_cmake REQUIRED)

install(DIRECTORY launch map models params rviz urdf worlds
  DESTINATION share/${PROJECT_NAME}
)

ament_package()

    在 package.xml 保留 ament_cmake，并增加运行依赖：

    <exec_depend>launch</exec_depend>
<exec_depend>launch_ros</exec_depend>
<exec_depend>robot_state_publisher</exec_depend>
<exec_depend>ros_gz_bridge</exec_depend>
<exec_depend>ros_gz_sim</exec_depend>
<exec_depend>rviz2</exec_depend>
<exec_depend>slam_toolbox</exec_depend>
<exec_depend>nav2_bringup</exec_depend>

    构建前先检查 SDF：

    cd ~/tb3_jazzy_ws
gz sdf -k src/my_tb3_slam_nav2/models/turtlebot3_burger/model.sdf
colcon build --packages-select my_tb3_slam_nav2 --symlink-install
source install/setup.bash

    gz sdf -k 必须成功；若失败，先修复 XML 或插件标签，不要跳过检查。

    6. 编写启动文件

    所有 ROS 2 launch 均使用 Python。下面给出启动职责与实现要求；复制上游 launch 后，只替换包名并移除 TURTLEBOT3_MODEL 环境变量依赖，模型固定为 Burger。

    6.1 sim.launch.py

    以 turtlebot3_gazebo/launch/turtlebot3_world.launch.py、spawn_turtlebot3.launch.py 和 robot_state_publisher.launch.py 为基线合并实现。它必须执行以下动作：

    1. 用 AppendEnvironmentVariable 将本包 models/ 加入 GZ_SIM_RESOURCE_PATH。
    2. 用 ros_gz_sim 的 gz_sim.launch.py 启动 worlds/turtlebot3_world.world。
    3. 用 ros_gz_sim create 读取 models/turtlebot3_burger/model.sdf，默认在 x=-2.0、y=-0.5、z=0.01 生成小车。
    4. 启动 ros_gz_bridge parameter_bridge，参数文件为 params/bridge.yaml。
    5. 读取 urdf/turtlebot3_burger.urdf 并启动 robot_state_publisher，其 use_sim_time 与 launch 参数一致。

    需要声明的 launch 参数：

    use_sim_time:=true
x_pose:=-2.0
y_pose:=-0.5

    不要桥接或发布第二套 /tf、/odom。SDF DiffDrive 和 robot_state_publisher 分别负责动态底盘变换与关节/静态本体变换。

    6.2 slam.launch.py

    该文件只负责启动 slam_toolbox 官方 online_async_launch.py 和 RViz。用 IncludeLaunchDescription 传入：

    use_sim_time:=true

    RViz 使用本包的 rviz/tb3_navigation2.rviz，并设置 use_sim_time。不要在此 launch 启动 AMCL 或 Nav2；建图时应只有 slam_toolbox 发布 map -> odom。

    6.3 nav.launch.py

    该文件用 IncludeLaunchDescription 引入 nav2_bringup/launch/bringup_launch.py，并提供三个参数：

    map:=<本包 map 目录中的地图 yaml>
params_file:=<本包 params/nav2.yaml>
use_sim_time:=true

    同时启动 RViz。地图尚未保存时，不要启动该文件。它不包含自动初始位姿节点，进入 RViz 后使用 2D Pose Estimate 初始化 AMCL。

    7. 桥接和 Nav2 参数检查

    params/bridge.yaml 应保留如下数据方向：

    ROS 2 话题 Gazebo 话题 方向 用途
    /clock /clock Gazebo -> ROS 仿真时间
    /joint_states /joint_states Gazebo -> ROS 轮子关节状态
    /odom /odom Gazebo -> ROS 轮式里程计
    /tf /tf Gazebo -> ROS odom -> base_footprint
    /scan /scan Gazebo -> ROS 2D 激光
    /imu /imu Gazebo -> ROS IMU
    /cmd_vel /cmd_vel ROS -> Gazebo 速度指令

    params/nav2.yaml 复制后先只做以下确认，不要立即调参：

    amcl:
  ros__parameters:
    global_frame_id: map
    odom_frame_id: odom
    base_frame_id: base_footprint
    scan_topic: scan

local_costmap:
  local_costmap:
    ros__parameters:
      global_frame: odom
      robot_base_frame: base_link

global_costmap:
  global_costmap:
    ros__parameters:
      global_frame: map
      robot_base_frame: base_link

    原始 Burger 的激光量程为 0.12 到 3.5 m，轮半径为 0.033 m，轮距为 0.160 m。SLAM、AMCL 和 costmap 的量程、机器人半径等参数应以这些仿真数据为基线；改模型尺寸后才需要同步调参。

    8. 运行 SLAM 与保存地图

    终端 1：启动自己的仿真

    cd ~/tb3_jazzy_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash

ros2 launch my_tb3_slam_nav2 sim.launch.py use_sim_time:=true

    终端 2：检查链路并控制小车

    cd ~/tb3_jazzy_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash

ros2 topic list | grep -E '^/(clock|scan|odom|tf|cmd_vel)$'
ros2 topic echo /scan --once
ros2 topic echo /odom --once
ros2 run tf2_ros tf2_echo odom base_footprint
ros2 run turtlebot3_teleop teleop_keyboard

    只有确认 /scan、/odom 和 odom -> base_footprint 正常后，再开始建图。

    终端 3：在线建图

    cd ~/tb3_jazzy_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash

ros2 launch my_tb3_slam_nav2 slam.launch.py use_sim_time:=true

    缓慢控制小车覆盖环境，尽量让雷达反复看到已建区域以完成闭环。建图完成后保存：

    ros2 run nav2_map_server map_saver_cli \
  -f ~/tb3_jazzy_ws/src/my_tb3_slam_nav2/map/tb3_world

    应生成：

    map/tb3_world.yaml
map/tb3_world.pgm

    保存后停止 slam.launch.py。SLAM 与 AMCL 都会发布 map -> odom，二者不能并存。

    9. 加载地图并使用 Nav2

    保持仿真运行，启动导航：

    cd ~/tb3_jazzy_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash

ros2 launch my_tb3_slam_nav2 nav.launch.py \
  use_sim_time:=true \
  map:=$HOME/tb3_jazzy_ws/src/my_tb3_slam_nav2/map/tb3_world.yaml

    在 RViz 中按顺序操作：

    1. 固定坐标系选择 map。
    2. 用 2D Pose Estimate 在地图上给出小车实际初始位置和朝向。
    3. 确认 /scan 激光点与地图墙壁重合。
    4. 用 Nav2 Goal 设置可达目标点。
    5. 观察全局路径、局部轨迹、local/global costmap 和最终姿态。

    10. 验收与排障

    最小验收

    • [ ] gz sdf -k 能通过 Burger SDF 语法检查。
    • [ ] colcon build --packages-select my_tb3_slam_nav2 --symlink-install 成功。
    • [ ] 仿真启动后 /clock、/scan、/odom、/tf、/cmd_vel 存在。
    • [ ] view_frames 显示一棵包含 odom -> base_footprint -> base_link -> base_scan 的连通树。
    • [ ] slam_toolbox 可更新并保存地图。
    • [ ] AMCL 初始位姿后，Nav2 可到达至少一个无障碍目标点。

    常见问题

    现象 优先检查 根因方向
    Gazebo 找不到网格或世界模型 echo $GZ_SIM_RESOURCE_PATH 本包 models/ 未加入资源路径，或漏复制 turtlebot3_common / turtlebot3_world
    小车显示正常但不能移动 ros2 topic echo /cmd_vel /cmd_vel 未从 ROS 桥接到 Gazebo，或消息类型不是 TwistStamped
    没有 /scan 或地图不更新 ros2 topic hz /scan、tf2_echo base_link base_scan SDF Sensors 插件、桥接配置、雷达 frame 或仿真时间错误
    RViz 提示 TF extrapolation ros2 topic echo /clock --once 有节点未设置 use_sim_time:=true
    AMCL 或 Nav2 无法定位 ros2 run tf2_tools view_frames map -> odom 缺失、初始位姿错误，或 SLAM 与 AMCL 同时发布该变换
    路径穿墙或无法避障 RViz 中检查 costmap 和 /scan nav2.yaml 的激光 source、机器人半径或膨胀层配置不匹配

    11. 后续自定义的正确入口

    本阶段完成后，再做模型定制。每次只改一个物理量，并同步修改两处：

    想改的内容 URDF SDF Nav2
    车体尺寸或碰撞体 visual/collision/inertial collision/visual/inertial robot_radius 或 footprint
    轮径、轮距 joint 和轮子 geometry DiffDrive 的 wheel_radius、wheel_separation 速度和加速度上限按实际能力复核
    雷达位置或量程 base_scan joint sensor pose/range costmap 与 AMCL 量程参数

    先保证上述复刻版稳定运行，再改模型；这样每个问题都能区分是模型参数导致，还是 SLAM/Nav2 链路导致。
